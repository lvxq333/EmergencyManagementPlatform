# 阶段一：站点、设备与监测记录

本轮交付最小数据闭环：登录 → 登记站点 → 登记设备 → HTTP 上报 → 入库 → 最新值与历史查询。首页“数据接入”已接入 Java 后端；其他专题仍使用原有演示数据，不代表已经接通预测模型。

## 已实现

- 站点新增、编辑：编号、名称、区域、经纬度和坐标系。
- 设备新增、编辑、启停：所属站点、设备类型、指标和预期上报周期。
- 指标字典当前内置 `vertical_displacement`（垂直位移，mm），接收解算后的位移，不接收或解算 GNSS 原始数据。
- HTTP 单条上报，明确区分 SIMULATED / REAL / UNKNOWN；REAL 仅表示上报方声明，不是系统认证的数据真实性。
- 可为启用设备配置服务器端自动模拟器，设置基准值、波动幅度和生成间隔；任务在离开页面后仍持续运行，并可随时停止。配置及进度保存在数据库，服务重启后可继续。
- 页面汇总累计记录、真实/模拟/未知来源数量及运行中的模拟器数量，设备行显示各来源数据构成。
- 同设备同消息 ID 同内容重试不重复入库；同 ID 不同内容返回冲突。迟到记录不会覆盖采集时间更新的最新值。
- 单位、时间、设备状态等校验；历史分页；超过三个预期上报周期无数据时显示超时提示。该提示不是独立心跳或预警算法。
- 新接口验证登录令牌、账户状态和权限；仅管理员维护档案，数据录入权限允许上报，风险查看权限允许读取。

有观测记录后禁止修改设备编号、站点和指标，避免破坏历史归属。暂不提供删除功能。

## 本地运行

在项目根目录启动隔离数据库（需要 Docker）：

```sh
docker compose -p risk-platform-phase1 -f deploy/phase1.compose.yml up -d
```

数据库只映射本机 13316，使用独立命名卷，不复用其他项目数据库。首次创建数据卷自动加载基础表和阶段一表；已有卷不会自动重跑初始化脚本。

另一个终端进入 `backend-java`：

```sh
mvn spring-boot:run -Dspring-boot.run.profiles=phase1-local
```

在项目根目录另开终端：

```sh
node tools/phase1-preview.mjs
```

访问 <http://127.0.0.1:18080/login.html>。预览服务代理 `/api` 到本机 Java 服务 18081，仅供本地开发。当前测试数据库已创建账号 `phase1-admin`，密码 `Phase1-local-2026!`，并留下一个模拟站点、一台模拟设备和一条模拟观测用于检查。全新数据库不会自动创建此账号，需要注册后在隔离数据库授权管理员角色。

上述账号及配置中的数据库口令仅供本机开发，不得用于公网或正式环境。后端、预览服务可用各自终端 Ctrl+C 停止；数据库停止命令如下，保留数据卷：

```sh
docker compose -p risk-platform-phase1 -f deploy/phase1.compose.yml stop
```

## 现有部署升级

先备份现有数据库，再使用 UTF-8 客户端对正确的数据库执行 `backend-java/src/main/resources/db/phase1.sql`。该脚本只新增表和缺失指标，不删除旧表，可重复执行。不要用基础 `schema.sql` 替换现有数据库。

重新构建并部署 Java 后端，同时发布 `home.html`、`assets/monitoring.js`、`assets/monitoring.css` 和修改后的 `assets/dashboard.js`。必须确保 `/api` 指向 Java 后端；原 Node 后端未实现本轮接口。不要把本地开发配置用于生产。

## 接口约定

所有接口携带 `Authorization: Bearer <登录接口返回的 token>`。

| 接口 | 用途 |
| --- | --- |
| GET /api/stations；POST /api/stations；PUT /api/stations/{id} | 站点列表、新建、编辑 |
| GET /api/devices；POST /api/devices；PUT /api/devices/{id} | 设备列表、新建、编辑 |
| PATCH /api/devices/{id}/status | 启停，请求体 `{"enabled":false}` |
| GET /api/metrics/definitions | 指标与标准单位 |
| POST /api/ingest/observations | 上报记录 |
| GET /api/devices/{id}/latest | 按采集时间获取最新值 |
| GET /api/devices/{id}/observations?limit=20&offset=0 | 历史分页，limit 最大 200 |
| PUT /api/devices/{id}/simulation；DELETE /api/devices/{id}/simulation | 启动/更新和停止自动模拟 |
| GET /api/monitoring/summary | 记录来源及运行任务汇总 |

上报示例（设备需先登记，时间换成实际采集时间）：

```json
{
  "deviceCode": "DEMO-D001",
  "messageId": "unique-message-001",
  "eventTime": "2026-09-15T03:00:00Z",
  "metricCode": "vertical_displacement",
  "value": 1.62,
  "unit": "mm",
  "sourceType": "SIMULATED"
}
```

重试时保持原 messageId、采集时间和内容不变；新的采样使用新的 messageId。接口返回记录 id 和 duplicate 标志。时间采用带时区 ISO 8601；禁止超出服务器当前时间 60 秒以上的数据。不进行隐式单位换算。

## 验证与边界

`backend-java` 下运行 `mvn test`。当前共 16 项测试通过，新增集成测试覆盖档案、上报、幂等与并发重试、迟到数据、分页、错误输入、权限和自动模拟任务；另已在隔离 MySQL 8.4 和浏览器验证登录、站点登记、设备登记、单条上报、后台连续上报、来源统计及查询。

自动模拟器属于流程验证数据源，不是传感器实时采集。数据页面使用原仪表盘刷新周期轮询；暂停原演示刷新只会暂停页面轮询，不会停止服务器自动模拟任务，手动刷新仍可用。未实现设备级凭证、断网补传、批量文件导入、队列、预测任务、真实数据优先选择或预警处置闭环。原有系统其他接口的整体安全加固不在本轮范围内，不能据此宣称可直接公网生产运行。

## 下一步

1. 真实设备接入凭证与接入日志：每台设备独立密钥；加入失败请求审计、重试、断网恢复和限流。

3. 统一预测接口与调度：数据校验、滑动窗口、预测任务状态、模型版本、结果存储；先用明确标记的基线模型验证流程，再接课题算法。
4. 预测结果转为风险分级和预警，联动现有页面；真实数据到位后再评估预测精度及实际端到端延迟。
