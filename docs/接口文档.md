# 广域立体风险感知平台接口文档

版本：v1.0.0  
日期：2026-06-22  
基础地址：

- 本机 Nginx 入口：`http://localhost:8080`
- API 前缀：`/api`
- Java 后端内部地址：`http://127.0.0.1:8081`

## 1. 通用说明

### 1.1 部署链路

```text
浏览器 -> Nginx :8080 -> /api/* -> Spring Boot / Tomcat :8081
```

前端页面通过相对路径调用接口，例如：

```js
fetch('/api/auth/login')
```

Nginx 负责把 `/api/*` 转发到 Java 后端。

### 1.2 请求格式

除特殊说明外，请求体均使用 JSON：

```http
Content-Type: application/json
```

### 1.3 认证方式

登录成功后接口返回 `token`。前端保存后，后续需要认证的接口可携带：

```http
Authorization: Bearer <token>
```

当前项目为了保持最小改动，用户、角色、权限接口先兼容已有前端行为；后续可以逐步补充更严格的权限拦截。

### 1.4 通用错误响应

```json
{
  "message": "错误原因"
}
```

常见状态码：

| 状态码 | 含义 |
| --- | --- |
| 200 | 请求成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或账号密码错误 |
| 404 | 资源不存在 |
| 500 | 服务端错误 |

## 2. 认证接口

### 2.1 登录

```http
POST /api/auth/login
```

请求体：

```json
{
  "username": "admin",
  "password": "123456"
}
```

成功响应：

```json
{
  "message": "登录成功",
  "token": "jwt-token",
  "user": {
    "id": 1,
    "username": "admin",
    "realName": "管理员",
    "roleNames": ["Administrator"]
  }
}
```

失败响应：

```json
{
  "message": "用户名或密码错误"
}
```

### 2.2 注册

```http
POST /api/auth/register
```

请求体：

```json
{
  "username": "viewer01",
  "password": "123456",
  "realName": "查看员"
}
```

成功响应：

```json
{
  "message": "注册成功",
  "userId": 3
}
```

失败响应：

```json
{
  "message": "用户名已存在"
}
```

## 3. 用户管理接口

### 3.1 获取用户列表

```http
GET /api/users
GET /api/users?search=管理员
```

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| search | string | 否 | 按用户名或真实姓名模糊搜索 |

成功响应：

```json
[
  {
    "id": 1,
    "username": "admin",
    "realName": "管理员",
    "email": "admin@example.com",
    "phone": "13800000000",
    "status": "active",
    "roleIds": [1]
  }
]
```

### 3.2 新增用户

```http
POST /api/users
```

请求体：

```json
{
  "username": "inspector01",
  "password": "123456",
  "realName": "巡检员",
  "roleIds": [2]
}
```

成功响应：

```json
{
  "message": "用户创建成功",
  "id": 4
}
```

### 3.3 编辑用户

```http
PUT /api/users/{id}
```

路径参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| id | integer | 用户 ID |

请求体：

```json
{
  "username": "inspector01",
  "password": "new-password",
  "realName": "巡检员A",
  "roleIds": [2, 3]
}
```

说明：`password` 可选。为空或不传时，不更新密码。

成功响应：

```json
{
  "message": "用户更新成功"
}
```

### 3.4 删除用户

```http
DELETE /api/users/{id}
```

成功响应：

```json
{
  "message": "用户已删除"
}
```

### 3.5 修改用户状态

```http
PATCH /api/users/{id}/status
```

请求体：

```json
{
  "status": "inactive"
}
```

字段说明：

| 字段 | 可选值 | 说明 |
| --- | --- | --- |
| status | active / inactive | 激活或禁用 |

成功响应：

```json
{
  "message": "状态已更新"
}
```

## 6. 风险看板接口

### 6.1 获取实时风险概览

```http
GET /api/risk/overview
```

说明：

- Java 后端根据 Redis 中的上一轮状态生成平滑变化的数据。
- Redis 为空时，后端初始化一组默认区域风险值。
- 中高风险告警可写入 MySQL，便于后续扩展历史查询。

成功响应：

      "statusText": "低风险"
    },
    {

      "value": 132,
      "level": "medium",
      "statusText": "中风险"
    }
  ],

  "metrics": [
    {
      "name": "甲烷浓度",
      "value": 0.74,
      "unit": "%",
      "status": "normal"
    },
    {
      "name": "管道压力",
      "value": 3.62,

## 7. FoxAPI 导入说明

项目同时提供 OpenAPI 3.0 JSON 文件：

```text
docs/foxapi-openapi.json
```

在 FoxAPI 中导入时选择 OpenAPI / Swagger 文件导入，并选择该 JSON 文件即可。导入后会生成认证、用户、角色、权限和风险看板接口分组。
